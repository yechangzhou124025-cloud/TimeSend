# 钉钉定时发送助手

这是一个 Windows 桌面程序。用户提前在钉钉目标群聊中编辑好消息并保持输入框位于前台，程序在计算出的时刻通过 Windows `SendInput` 发送一次普通 Enter。

## 特性

- 毫秒级目标时间和一次性任务，完成后自动解除启用；
- 自动 RTT 测速或手动网络补偿，并提供最大提前量保护；
- 基于单调时钟的高精度等待，记录计划时间与实际调用误差；
- 系统托盘、配置持久化、日志轮转和 Windows 单实例保护；
- PyInstaller 单文件 EXE 构建脚本。

程序不会查找群聊、输入文字、操作剪贴板、点击鼠标、识别钉钉窗口或切换前台窗口。

> 重要：Enter 会发送给触发时刻的当前前台窗口。如果钉钉不在前台，Enter 可能进入其他程序。请关闭可能弹出的软件，并关闭休眠、锁屏和自动更新重启。

## 环境要求

- Windows 10 或 Windows 11；
- Windows 桌面版钉钉；
- 源码运行或打包需要 64 位 Python 3.11 及以上版本；
- 电脑在发送前必须保持开机、唤醒且用户会话未锁定。

Linux/macOS 只能运行部分核心测试，不能使用 `SendInput`、`w32tm` 或生成可验证的 Windows EXE。

## 安装开发环境

安装 Python 时勾选 `Add Python to PATH` 和 Python Launcher。然后在项目目录打开 PowerShell 或命令提示符：

```bat
py -m venv .venv
.venv\Scripts\activate
py -m pip install -r requirements-dev.txt
```

## 运行源码

```bat
.venv\Scripts\activate
py main.py
```

首次启动会尝试执行 `w32tm /resync`。同步失败不会导致程序退出。

## 使用方法

1. 打开钉钉并进入正确的群聊；
2. 在输入框中编辑好消息，不要提前发送；
3. 确认钉钉设置为按普通 Enter 发送消息；
4. 在本程序中编辑本次目标时间，可精确到毫秒；
5. 选择“自动测速”或“手动设置”；
6. 根据需要填写额外补偿和最大提前量；
7. 打开“启用本次发送”；
8. 让钉钉输入框始终保持在前台，然后离开电脑。

发送完成后，本次任务自动结束，不会循环发送，也不会自动安排第二天。下次使用时重新设置时间并启用即可。程序重启后会恢复参数，但不会自动启用发送。

## 网络补偿

界面提供两种模式：

- **自动测速**：目标时间前2秒测速1次，自动填写网络补偿；
- **手动设置**：程序不在发送前测速，直接使用用户填写的数值。

“立即测速”每次只测1次。自动模式会更新输入框；手动模式只在底部状态栏给出参考值，不覆盖手动设置。

网络测速失败、超时或发生异常时，本次网络补偿使用 `0 ms`，并写入日志。网络补偿只是估算值，不能代表钉钉服务器的真实接收时间。

## 额外补偿和校准

额外补偿用于吸收 Windows 调度、程序执行、按键注入和钉钉客户端处理等延迟。默认值为 `4 ms`。

校准规则：

- 实际发送偏晚：适当增大额外补偿；
- 实际发送偏早：适当减小额外补偿。

建议每次只调整少量并多次测试。只要最终提前量大于零，程序就会在目标时间之前按 Enter。如果绝对不能提前，可将手动网络补偿和额外补偿都设为 `0 ms`。

## 最大提前量

最大提前量默认是 `80 ms`。如果计算结果超过上限，程序使用上限值并在界面和日志中警告，避免网络异常造成过度提前。

## 测试功能

### 5秒后测试 Enter

确认后倒计时5秒，然后向当时的前台窗口真实发送一次 Enter。请先在测试群输入测试消息并保持钉钉位于前台。

### 定时精度测试

选择今天稍后的时间，程序使用正式任务相同的高精度等待逻辑发送 Enter。日志会记录计划调用时间、实际调用时间及误差。

所有测试都会真实按下 Enter，不是无副作用的模拟测试。

## 日志和配置位置

默认位置：

```text
%LOCALAPPDATA%\DingTalkAutoSend\
├─ config.json
└─ logs\DingTalkAutoSend.log
```

日志达到约2MB后轮转，最多保留5份历史文件。每次正式任务记录：

- 目标时间和计划 Enter 时间；
- 测速成功、失败及本次补偿；
- 网络补偿、额外补偿、理论和最终提前量；
- 本地实际调用 `SendInput` 的时间；
- 相对计划时间和标准目标时间的误差；
- Windows 接受的按键事件数量及错误码。

日志中的成功表示 Windows 接收了 Enter 注入事件，不代表钉钉服务器确认收到消息。程序无法获取服务器真实接收时间。

如果 `config.json` 损坏，程序会将其改名为 `config.broken.json` 并恢复安全默认值。

## 系统托盘和退出

关闭主窗口只会隐藏到系统托盘，后台任务继续运行。托盘菜单提供：

- 打开主界面；
- 启用或暂停本次发送；
- 查看日志；
- 退出程序。

只有点击“退出程序”才会真正结束进程。程序使用 Windows mutex 防止同时启动两个实例。

## Windows 时间同步

程序启动时尝试运行：

```bat
w32tm /resync
```

同步可能因为未以管理员身份运行、Windows Time 服务未启动、域策略或网络限制而失败。失败只会写入日志，不会导致程序退出。

可以尝试以管理员身份打开命令提示符并执行：

```bat
net start w32time
w32tm /resync
```

启用发送后，界面的手动同步按钮会暂时不可用，避免调度期间系统时钟跳变。

## 打包单文件 EXE

在真实 Windows 环境双击 `build.bat`，或在命令提示符运行：

```bat
build.bat
```

脚本会在项目内创建独立的 `.venv` 构建环境，将所有依赖安装在其中，再使用 `DingTalkAutoSend.spec` 执行 PyInstaller。依赖不会安装到系统 Python。生成文件位于：

```text
dist\DingTalkAutoSend.exe
```

配置使用单文件、无控制台窗口模式。首次启动单文件 EXE 比后续启动稍慢是正常现象。

## 常见问题

### 到时间没有发出

检查是否启用了本次发送、电脑是否休眠或锁屏、钉钉是否仍在运行，以及目标时间是否已经过去。查看日志中的 `success`、`sent_events` 和错误码。

### Enter 发到了其他程序

程序按设计不识别钉钉窗口。必须确保目标输入框一直位于前台，并避免弹窗和远程控制窗口抢占焦点。

### 钉钉没有按 Enter 发送

检查钉钉的发送快捷键设置，确认它配置为“按 Enter 发送消息”，而不是 `Ctrl+Enter`。

### 时间同步失败

参考“Windows 时间同步”一节。权限不足不影响程序启动，但系统时间不准确会直接影响发送时刻。

### 日志能否显示钉钉服务器接收时间

不能。本程序只知道本地调用 `SendInput` 的时间，没有接入钉钉服务器或开放平台接口。

## 精度说明

程序启动时尝试调用 `timeBeginPeriod(1)`，远距离采用普通等待，最终约50ms使用 `time.perf_counter_ns()` 忙等待。Windows 桌面程序不是硬实时系统，无法承诺固定的 ±1ms 精度；应以本机日志中的多次测试结果为准。
